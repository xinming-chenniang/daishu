## 一、实施前基线（内容量）

| 项 | 当前值 | 出处 |
|---|---|---|
| 信型 | 5（家书 / 请安 / 贺寿 / 诉苦 / 求荐）| `NPCManager.LETTER_TYPES` |
| 关系 | 5（父母 / 子女 / 夫妻 / 兄弟 / 朋友）| `NPCManager.RELATIONS` |
| 称谓池 | 3 / 关系（共 15 条）| `SALUTATION_POOL` |
| 落款池 | 3 / 关系（共 15 条）| `SIGNATURE_POOL` |
| 正文词库 | 6 / 槽 × 3 槽 × 5 信型（共 90 个位置）| `BODY_POOLS` |
| 故事模板 | 16 条（家书 4 / 其余各 3）| `STORY_TEMPLATES` |
| 一局委托数 | 10 天 × 3 = **30 单** → 平均每种信型出现 **6 次** |

**问题**：单信型平均 6 单、模板 16 条，玩到第 3 天就能感觉"这几个故事见过"；
正文每槽只有 6 个候选，记性好的玩家可以背答案（虽然故事文本每次随机嵌入正解，仍有"读故事"这一层）。

## 二、现状：数值（`node tools/balance_sim.mjs`，20000 局）

| 策略 | 成功率 | 终局钱 p50 |
|---|---|---|
| 最优（每槽必中）| 100% | **771** |
| 熟练（90% 命中）| 100% | 687 |
| 一般（75% 命中）| **69.5%** | 522 |
| 粗心（60% 命中）| 0.2% | 375 |
| 偶尔留空（90% + 5% 空槽）| 60.9% | 517 |
| 不看故事（池内随机）| 0% | 225 |

**结论**：① "读懂故事"是硬门槛（随机猜 0%），符合设计意图；
② 但**完美线太宽**——全对能到 771，目标 500，盈余 54%，终局没有紧张感；
③ 难度悬崖在 60%–75% 命中之间，很陡。

## 三、三个方案

### 方案 A：内容扩充（**推荐**，不改数值）

| 项 | 现在 → 提案 |
|---|---|
| 正文词库 | 6 → **10** / 槽（每信型 +12 词）|
| 称谓池 | 3 → **5** / 关系 |
| 落款池 | 3 → **4** / 关系 |
| 故事模板 | 16 → **26** 条 |

- **数值影响 ≈ 0**：模拟里的"命中率"是玩家能力参数，与词库大小无关；
  但**瞎蒙更难** —— 已量化（`node tools/balance_sim.mjs --pool 5,10,4`）：
  单槽命中率 `33/17/17/17/33%` → `20/10/10/10/25%`，**单委托五项全对从 0.05%（约 1/1944）降到 0.01%（约 1/20000）**。
  方向正确：读故事的玩家不变，蒙答案的人被挡掉。
- **注意：方案 A 不是"只改数据"** —— 左栏布局已经到极限，必须带 UI 改造，见下方「布局约束」。
- 候选词表已备好：[`data/content_candidates_2026-10-18.json`](../data/content_candidates_2026-10-18.json)，
  **85 条、181 个不同汉字，全部能在 `hanchanlongcang.otf` 字形表里找到**（见 §四）。
- **验收闸门已就位**：接入前后都跑 `--script res://tools/verify_content.gd`
  —— 它检查"正解⊆词库 / 同槽无重复 / 故事含三个正解 / 报酬公式 / 称谓·正文·落款用字都有字形"，
  并抽样 1200 个 NPC（实测当前数据全过、152 个用字 0 缺字）。**扩充词库后它就是验收标准。**

#### 布局约束（2026-10-18 实测，方案 A 的隐藏成本）

用固定种子截图（`capture_scene.gd --seed`）+ 像素量测，左栏现状：

| 项 | 实测值 |
|---|---|
| 左栏宽 / 内容宽 | `HSplit.split_offset = 355`，`WordVBox` 左右各 8px → **内容宽 339px** |
| 一个词按钮 | 高 **31px**；正文 6 个按钮**刚好塞满一行**（HFlow 会在第 6 个就换行 → 说明 HBox 版本其实已溢出约 1px）|
| 纵向余量 | 最后一行按钮底 `y=525`，可用底 `y=570` → **只剩 45px** |
| 滚动容器 | **没有**（`WordPanel/WordVBox` 是纯 `VBoxContainer`）|

→ 每槽正文多一行要 **+31px 行高 + 间距**，三个槽合计 **≈ +105px**，远超 45px 余量，内容会顶出面板。
**所以方案 A 必须同时做 UI 改造**，建议三件套：

1. `WordVBox` 外面套 **`ScrollContainer`**：词数再多也不溢出（滚动条会吃掉约 12px 宽）；
2. **词按钮瘦身**：字号 18→16、内容边距 4→2 → 按钮宽约 48px，滚动条占位后仍能一行放 5 个；
3. **验收**：`capture_scene --seed` 改前/改后对比 + `verify_drop`（**滚动到下方后拖拽仍要能落**）+ 重截存档图。

> **试错记录（防止下一个人再试一次）**：先试过"只把 `HBoxContainer` 换成 `HFlowContainer`"（自动换行、不动逻辑），
> 实测**不是无痛改动** —— 第 6 个词就换行、多出的行顶出面板；固定种子逐像素对比有 **13 万像素差异**。已回滚。
> 结论：问题不在"容器会不会换行"，而在**左栏没有纵向空间**。

**如果不想动 UI → 方案 A−**：只扩**故事模板**（16→26）与反馈文本，不碰称谓/正文/落款词库。
零 UI 风险、零数值影响，但新鲜度提升有限（故事换皮、答案不变、仍然是 6 选 1）。

- 工作量（A 全量）：改数据 + ScrollContainer + 按钮瘦身 + 重截 + 跑 `verify_content`/`verify_drop`（约半天到一天）。
  工作量（A−）：只改 `NPCManager.STORY_TEMPLATES` + `verify_content` + 抽查截图（约 1 小时）。

### 方案 B：收紧张力（只调数值，可与 A 叠加）

- **推荐档：目标 500 → 525**：完美/90% 不受影响（仍 100%），75% 命中从 69% → **47%**。
  这意味着"读得懂但偶有失误"的玩家要更认真，而高手依旧稳。
- 备选：目标 550（75% → 25%，偏硬核）。
- 不建议 `bonus × 0.75`：会把 75% 命中率打到 21%，惩罚的是中等玩家而不是"完美太宽"。
- 工作量：`PlayerManager.TARGET_MONEY` 一个常量 + 文档/README 同步 + 平衡报告更新。

### 方案 C：结构性改动（**不建议现在做**）

连续格式错误加倍扣钱、当日全错影响次日、委托人满意度等——都改玩法，
发布前动风险高，且需要重新定义"失败体验"。留到有真实玩家数据之后。

## 四、字体覆盖核对（为什么必须先查）

信纸上的称谓/正文/落款都用**寒蝉龙藏体**渲染，而它 CJK 覆盖率只有 **32.4%**。
一旦词里出现缺字，运行时靠 `FontFallback` 挂的系统字体兜底 —— 字能显示，
但**书法字里混进黑体**，信纸观感直接破。所以候选词先逐个撞 cmap：

```
$ python tools/check_content_chars.py
字体：hanchanlongcang.otf  字形表含 7038 个码位
候选条目：85 条，涉及汉字 181 个
[OK] 全部覆盖：候选里的每个汉字在字体里都有字形
```

## 六、实施结果（2026-10-18，方案 A）

### 改了什么

| 文件 | 改动 |
|---|---|
| `scripts/NPCManager.gd` | 四组常量扩充：称谓 3→5/关系、落款 3→4/关系、正文 6→10/槽、模板 16→26；随后（同日）整体迁到 JSON |
| `data/npc_content.json` | **内容真源**：词库/模板/称谓/落款/提示词/反馈都在这里，`NPCManager.load_content()` 启动加载 |
| `scenes/letter.tscn` | `WordPanel` 下插入 **`WordScroll`（ScrollContainer，横向滚动禁用）**，`WordVBox` 移入其下 |
| `scripts/letter.gd` | 节点路径随新结构更新；正文每槽的行容器 `HBoxContainer` → **`HFlowContainer`**（10 词自动换行）|
| `tools/verify_drop.gd` | 同步新节点路径（旧路径会让脚本取不到节点并**挂住不退出**——实测踩到）|
| `tools/verify_letter_layout.gd` | **新增**：布局验收（数量 / 可滚动 / 不横向溢出 / 滚到底可见）|

### 新规模

| 项 | 值 |
|---|---|
| 称谓 / 落款 | 5 条/关系（25）· 4 条/关系（20）|
| 正文词库 | **10 词/槽** × 3 槽 × 5 信型 = 150 个词位 |
| 故事模板 | **26 条**（家书 6 / 其余各 5）|
| 用字 | 192 个不同汉字，**0 缺字**（`verify_content` 实测）|

- `verify_drop`：五槽落词 → `PERFECT` / `fee = 20`（拖拽与判定未被布局改动破坏）。
