## 阶段 1：内容广度（2-3 天）

- **信型系统**：启用闲置的 `letter_type` 字段——家书/请安/贺寿/诉苦/求荐 5 种信型，各有专属称谓/落款/正文词库/故事模板/报酬曲线
- **词库扩充**：每槽 4→8+ 词、称谓/落款 2→4+、故事模板 3→10+、反馈文本 3→6+（分档）
- **NPC 深化**：启用 `avatar`（头像）、`description`（身份）、`required_calligraphy`（书法难度→影响报酬/判定权重）
- **数据驱动**：硬编码常量池 → `data/npcs/*.json`（内容与代码解耦）
- 验收：同一天 3 个 NPC 无明显重复感；至少 3 种信型；每封信故事文本各不相同
- 工具：stylotrace 批量生产风格统一的书信文案

## 阶段 2：平衡验证（1 天）

- 蒙特卡洛模拟：10 天 × 3 NPC/天，最优/中等/随机三种策略各 1 万局，输出成功率与收支分布
- 校准 `base_fee` / `perfect_bonus` / 摊位费 10 / `TARGET_MONEY=500`
- 探索杠杆：每日 NPC 数、漏单惩罚、物价波动事件
- 验收：最优策略成功率 70-80%、随机策略 10-20%、结局金额分布有区分度

## 阶段 3：美术替换（3-5 天，与阶段 1-2 可并行）

- 替换全部占位图：标题背景、信纸、UI 面板、NPC 头像（round1 生成图 + 后续轮次，去水印）
- 像素风格统一（16px 网格、色调一致）
- 工具：vision-router 审查生成图（构图/风格/与代码锚点对齐）
- 验收：游戏中无占位图；所有底图与代码坐标锚定一致

## 阶段 4：音频与反馈（1-2 天）

- 音效：拖拽落字、毛笔书写、铜钱、提交/错误提示、结局音乐（8-bit 风格）
- 接入点：`letter.gd`（拖拽/提交）、`main.gd`（结算）、`EndGameScreen`（结局）

## 阶段 5：打磨与发布（2-3 天）

- 动效：拖拽反馈、结算弹窗过渡、结局淡入
- 导出 Windows 版、应用图标、应用名"代书"
