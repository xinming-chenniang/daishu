## 一、这个项目是什么

**《代书》（daishu）—— 明中期代笔先生模拟器。**

穷书生在成化年间摆代书摊，**10 天**内靠替人代写书信攒够 **500 文**进京赶考。
玩法是《Paper, Please》式的文书劳作，但反过来：**不是检查别人写的文书，而是自己把文书组装出来**
（选称谓 → 按信型填正文三空 → 落款署名）。

- **引擎**：Godot **4.6.1-stable (mono)**，纯 GDScript（未使用 C#）
- **远端**：<https://github.com/284022719/daishu>（public，SSH remote）
- **当前状态**：**可玩纵向切片（playable alpha）** —— 核心循环端到端跑通

```
标题存档 → 序章 → 每日 3 位委托人 → 拖拽代写 → 四档判定计费
        → 当日结算 → 10 天结局（≥500 文成功 / 否则失败）
```

## 四、怎么跑起来（本机实际环境）

⚠️ **`godot` 不在 PATH，路径因机器而异**（家机在 `D:\Program Files\...`，本机在工作区 `tools\godot\`，
也可能还没装）。**先解析、别抄死路径**：

```powershell
pwsh -File tools\where-godot.ps1        # 打印 $godot / $proj 两行，可直接粘贴
pwsh -File tools\run-godot.ps1 --headless --path . --script res://tools/verify_drop.gd
```

`$proj` 永远是仓库根（含 `project.godot` 那层），所以在仓库根可用 `--path .`：

```powershell
# 跑游戏
& $godot --path .

# 新增/改动资源后必须导入（且见第十节的"同尺寸不重导"坑）
& $godot --headless --path . --import
```

- 导出模板已装：`%APPDATA%\Godot\export_templates\4.6.1.stable.mono`
- 本地已能导出 `export/daishu.exe` + `daishu.pck`（gitignore，不进仓库）
- **首个 Release 尚未发布**（GitHub 上 description 已写、**topics 仍为空**）

## 五、怎么验证（改完必须跑）

这几个脚本是"改完自己先验一遍"的手段，比肉眼看截图可靠：

| 命令 | 验什么 | 期望 |
|---|---|---|
| `--script res://tools/verify_drop.gd` | 五个槽位落词 + 拖拽预览 + 判定 | `总体: PASS` / `result_code = PERFECT` |
| `--script res://tools/verify_theme.gd` | 全局 Theme 三查（设置项→资源→控件实际取值）| `结论: PASS` |
| `--script res://tools/verify_avatar.gd` | 头像关系映射 + 缺字段不崩 | `结论: PASS` |
| `--script res://tools/verify_flow.gd` | 代写→结算→回主界面的状态机（返回不提交不消耗委托、防重复结算、破产/第 10 天早退）| `结论: PASS` |
| `--script res://tools/verify_audio.gd` | 4 个 UI 音效加载/播放、缺名字不崩 | `结论: PASS` |
| `--script res://tools/verify_judge.gd` | 四档判定与优先级（格式错误优先、不叠加底薪）| `结论: PASS` |
| `--script res://tools/verify_save.gd` | 存读档往返 / 坏档不污染状态 / 版本过新拒绝 / 旧档兼容 | `结论: PASS` |
| `--script res://tools/verify_cursor.gd` | 毛笔光标素材（尺寸/透明底/热点）| `结论: PASS` |
| `--script res://tools/verify_content.gd` | NPC 数据不变量（正解⊆词库、同槽无重复、故事含正解、报酬公式）+ 字体覆盖 | `结论: PASS` |
| `--script res://tools/capture_scene.gd -- --scene <名> --out x.png` | 任意场景截图（可选 `--click 按钮名`）| 出图 **必须 1152×648**，否则脚本报错 |
| `--script res://tools/probe_geom.gd` | 量贴图绘制区 / 槽位实际矩形 | 用于判断锚点该写多少 |
| `node tools/art_check.mjs watermark <图> --scan` | 水印检测 | `未检出文字/水印` |
| `node tools/art_check.mjs grid <图> --expect 12` | 信纸栏线检测 | `结构符合期望（栏数 12）` |
| `--script res://tools/wm_clean.gd -- --image <res://图> --crop-through <Y> --out <路径>` | 去水印（裁底带 + 缩回原尺寸）| 见 `docs/ART_PLAN.md` |

> ⚠️ **截图脚本必须不传 `--resolution`** —— 它会连视口一起改，出图被缩放（实测给 900×260 出图只有 462×260），
> 拿这种图做像素判断会得出错误结论。脚本已内置尺寸断言。

## 九、已知问题与遗留代价

1. **三张底图是"裁底带 + 缩回原尺寸"得来的** —— 画面纵向被拉伸 **8–10%**（肉眼几乎不可辨）。
   **要彻底去掉这个代价，仍应重生成无水印原图**（提示词见 `data/art_prompts_round*.json`）。
2. **`DEV_PLAN.md` 的"已知问题"段落已过时** —— 还写着"信纸底图带豆包水印（阶段 3 处理）"，实际已清除。
   同样 `README.md` 第 34 行"三张底图还带生成器水印"、第 76 行"docs/ 11 篇"也已过时。
   **改动前先信 `ART_PLAN.md` 与 `PRE_RELEASE_UI_CHECK.md`。**
3. **`art_check.mjs` 的水印检测器有误报** —— 只针对白色/近白文字；重采样锐化后会把背景里的
   招牌/人物误判成文字行（清完水印后 `main_bg.png` 会新报 `[1928,479..1983,516]`，**那是集市摊位里的人与货**）。
   **报命中时必须裁出来人眼复核，不要直接当成水印处理。**
4. **`godot-docs/` 语料是 `blob:none` 部分克隆** —— 本地只有那棵提交树、**没有 blob 对象**。
   查文档可以；`git status` / `checkout` 会去 gitcode.com 取 blob，本机代理拦 403 →
   报 `could not fetch … from promisor remote`。**它现在只能当只读纯文本语料用，不能当能切分支的仓库用。**
5. **mono 引擎会打印 `.NET Sdk not found`** —— 本项目是纯 GDScript，**这条报错可忽略**，
   不影响运行与导入（别去装 .NET SDK）。

## 十、踩坑清单（改 Godot 前必读，完整版在 `docs/AI_PLAYBOOK.md`）

17 条都在 playbook 里，这里只挑**最容易让下一个会话白忙**的：

| # | 坑 | 判据 |
|---|---|---|
| 1 | `godot --check-only --script` **不注册 autoload** | 引用单例报 `Identifier not found` 是**假阳性**；拿没动过的同类脚本做对照组 |
| 8 | `--script` 模式**不导入新资源** | `ResourceLoader.exists()` 返回 false 但不报错；新增资源先跑 `--import` |
| 12 | **`--resolution` 会连视口一起改，截图被缩放** | 截图工具自己设窗口尺寸并**断言出图尺寸**；别拿缩放图做像素判断 |
| 14 | **截图工具漏初始化 → 界面"看着像游戏坏了"** | `letter.tscn` 靠 `main.gd` 调 `init_with_npc()` 才填词库；工具漏了这步会得到空词库，**差点去改没坏的游戏代码** |
| 15 | `--import` **异步**，没跑完就断言"资源缺失" | 报缺失先 `Test-Path` 核实 `.import`/`.ctex` 是否真的不在 |
| 17 | **同尺寸改写图片，Godot 不重新导入** | 新旧 `letter.png` 尺寸与**字节数完全相同**（都 3,838,386 B）→ `.ctex` 仍是旧像素；必须删 `.godot/imported/<图>-<哈希>.ctex` + `.md5` 再导入 |
| 11 | **`Font.fallbacks` 不会进 `.tres`**，且 Godot **不会自动回退系统字体** | 只能运行时挂（`scripts/FontFallback.gd`）；项目外用字实测渲染成方块 |
| 10 | `.tres` 里 stylebox 键名**别手写**（会静默失效）；改完**同进程 `load()` 回读会命中旧缓存** | 用 `tools/build_theme.gd` 让引擎自己序列化；回读读**文件文本**，语义校验另起进程 |

**几条能省时间的本机事实**：
- `probe_font.gd` 之类的探针脚本**解析失败会挂住不退出**（既不执行也不 `quit()`）→ 跑脚本带超时。
- GDScript **同作用域不允许变量重名**（哪怕在不同 `if` 分支）。
- 字体决策依据：**先量项目自己的用字集**（594 个不同汉字），再拿它撞字体覆盖 ——
  `hanchanlongcang` 的 CJK 总覆盖率只有 32.4%，但对项目用字 **0 缺字**，所以可用。
  **别用"总覆盖率"当判据。**
