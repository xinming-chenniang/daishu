### ③ 书写槽位的边界压在印刷栏线上，并溢出纸面 ✅ 已修（2026-10-11）

> **订正**：本清单初版把这条写成"槽位没有任何视觉样式、视觉上不存在"。**实测（headless 截图 + 像素量测）证明判断有误** —— `scripts/letter_slot.gd` 的 `_draw()` 一直在画黑色虚线边框，槽位是看得见的。真正的问题在**几何**：

**实测数据**（`tools/capture_letter.gd` 出图 + 像素量测）：

| 项 | 实测值 |
|---|---|
| 视口 | 1152 × 648 |
| 贴图实际绘制范围 | x 390..1130，**y 20..574**（741 × 555，比例 1.335 与底图一致） |
| `PaperArea` / `Background` 的 rect | x 390..1131，**y −65..661**（741 × 726） |
| → 差异 | `PaperArea` 相对贴图**上下各有 85px 死区** |

由此产生两个真实缺陷：

1. **横向**：槽位边界取的是印刷**栏线**位置（底图像素 316 / 664 / 1017 / 1361 / 1715），而不是**栏中心**（0.17085 / 0.31854 / 0.46657 / 0.6129 / 0.76155）。槽位正好压在栏线上。
2. **纵向**：锚点 `0.12 / 0.85` 落在上面那 85px 死区里，导致槽位纵向**溢出纸面上下边缘**。

**已采取的修复**（commit `a96a86a`）：

- 横向锚点改为栏中心 ±12% 内缩，槽位装进栏内、不再压线
- 纵向锚点按实测换算为 `0.117 / 0.882`，槽位收回纸面内
- 新增 `StyleBoxFlat` 槽位底色（暖白 30% 透明），"可放置区域"一眼可见
- 占位提示改浅褐半透明（`PLACEHOLDER_COLOR`），与放下后的墨色（`FILLED_COLOR`）区分

**复核方式**：改完必须重跑截图，确认虚线边与印刷线的关系。这是 ART_PLAN §四 ③ 要求的"截图 → 像素验证"三步的第三步。

### ⑥ 的修复记录（过渡实现）

**结论先说**：`ART_PLAN.md` 要的是 **64×64 像素画半身像**（农夫/老妇/书生/货郎/孩童，见
`data/art_prompts_round2.json` 的 `npc_avatar`）。**本机没有图像生成工具，那份素材只能由人生成**，
所以我做的是**程序化的过渡实现**，接口按真素材可替换来设计。

**做了什么**：

| 项 | 内容 |
|---|---|
| 新增 | `scripts/npc_avatar.gd` —— 44×44 圆形"名帖"（亮外环 + 主色圆 + 暗内环 + 一个书法体汉字）|

| 取色 | 全部落在 `ART_PLAN.md` §二 户内色板：木构 `#9c5424`/`#b46c3c`、朱砂 `#a43c2c`、户外 `#6c846c`/`#846c54` |

**头像上的汉字取「关系」而不是姓氏** —— 但**理由不是"更不容易重复"**，我一开始写错、被实测推翻了：

```
三名委托人里（可重复抽样）
  姓氏撞的概率   38.8%   （7 个姓氏）
  关系撞的概率   52.0%   （5 个关系）  ← 关系反而更容易撞
  姓名撞的概率    6.0%   （49 种姓名） ← 姓名几乎唯一，且本来就印在按钮上
```

**真正成立的理由**：① **关系是玩法信息** —— 称谓池与落款池都按关系划分
（`NPCManager.SALUTATION_POOL` / `SIGNATURE_POOL`），玩家读关系有用、读姓氏没用；
② **字与色的集合小且受控**（5 字 + 5 色），5 个字都在项目已验证的 594 字覆盖内，不必随姓名池扩张加素材。
**头像的职责是"一眼给出关系类别"，不是唯一标识某个人** —— 唯一标识交给姓名。

**顺带修掉一个布局脆弱点**：加头像后每行 37→44px，`VBox` 最小高 280 > 面板写死的 238，
**状态栏被顶出屏幕上沿**。原因是面板是 root `Control` 的直接子节点（不在任何 Container 里），
`size_flags` / `custom_minimum_size` 都不会被自动采纳。已改为 `main.gd` 的
`_resize_panel_to_content()` **按内容最小尺寸算面板高度**并向上取整到 8px —— 以后字号或条目数变了都不会再顶破。

**回归**：新增 `tools/verify_avatar.gd`（5 种关系 → 字色互不相同；缺字段/未知关系不崩，回退 `客` 字）。
`verify_drop` / `verify_theme` / `verify_avatar` 三个全部 PASS。

**替换路径**（真素材到位后，接口不变、`main.gd` 不用动）：
把 64×64 头像按 `<关系>.png` 放进 `assets/images/ui/avatars/`（或给 NPC 填 `avatar` 路径），
`npc_avatar.gd` 改成"有贴图就画贴图、没有就回落当前画法"。

### ⑫ 的订正与现状（`0b3c34a`）

**ART_PLAN 原话**是「round1 的 5 张已实测无水印，缩到 16–24px 即可」。**实测下来只有一半对**：

1. **5 张里只有 `cursor_r1_05` 是"一个孤立毛笔"**，另外 4 张（`r1_01`–`r1_04`）是**无缝墨纹图案**，缩到 24px 只会是一团墨斑，当光标不可用。
2. **5 张全是 `colorType=2`（无透明通道）**、纯色浅灰底 —— 直接缩放会带一个灰方块。必须先做去底转 alpha。
3. **即使用可用的那张**：我把它按亮度转成 alpha、裁到毛笔主体（原图 `x320..570, y115..470`）、输出 64×64，
   但在信纸底色上按真实尺寸预览（见 `screenshots/brush_cursor_sizes.png`）：**96px 是漂亮的墨迹，16–32px 就是一团墨点**。
   这不是处理失误，是原图（笔 + 飞白 + 纵向墨滴）缩小的必然结果。

**所以没有把它设为系统光标**（那尺寸下认不出是笔），改为用在放得大的地方：

- `word_button.gd` 的**拖拽预览**：毛笔贴图（72px）+ 词文本并排，取代原来的纯文字预览
- 预览构造抽成 `build_drag_preview()`，可被 `verify_drop.gd` 单测
  （教训：直接调 `_get_drag_data()` 时没有真实拖拽在进行，`set_drag_preview()` 会触发引擎断言
  `Condition "!get_viewport()->gui_is_dragging()" is true`）

**若想要真正的毛笔光标**，需要重新生成一张**单一笔尖、透明背景、方向朝上**的小图（128×128 内），

### ⑦⑧⑨ 的修复记录（本次）

**⑦ 全局中文字体 + ⑧ 按钮九宫格**：新增全局 Theme `theme/daishu_theme.tres`，在 `project.godot` 里由
`gui/theme/custom` 挂上，六个场景同时受益。

| 项 | 做法 |
|---|---|
| 字体 | `default_font` = `hanchanlongcang.otf`（已在本项目），`default_font_size` = 18 |
| 兜底 | `scripts/FontFallback.gd` 自启动挂系统字体链（`Microsoft YaHei`/`SimSun`/…）|
| 按钮 | `StyleBoxTexture` 九宫格（`assets/images/ui/button_frame.png`，40×40，边距 12），normal/hover/pressed/disabled/focus 五态 |
| 文字色 | Button / Label 一律墨褐 `Color(0.235,0.176,0.098)`，取代 Godot 默认白字 |

**为什么字体敢全局换**：先量了项目**实际用字**（从 scripts+scenes 提取，594 个不同汉字），
再拿这个集合去撞字体覆盖 —— `hanchanlongcang` **0 缺字**。它的 CJK 总覆盖率只有 32.4%，
但项目用字完全落在覆盖范围内，所以可用；兜底链是给"日后新增文案"上的保险。

**⑨ 窗口分辨率**：`project.godot` 显式写入 `window/size/viewport_width=1152` / `viewport_height=648`。
**这一步是 ⑦⑧ 的前置条件** —— 过程实测：给 `--resolution` 传别的尺寸会把**视口**一起改掉，
导致截图被缩放（给 900×260 时出图只有 462×260），槽位对齐依赖的分辨率也必须钉死。

**几个值得记的坑（都已写进 `AI_PLAYBOOK.md`）**：

1. **`.tres` 里 stylebox 的键名不要手写** —— 本地语料没有示例。改为用代码构建 `Theme` 再
   `ResourceSaver.save()`，由引擎自己序列化（实际写出 `Button/styles/normal`、`Label/colors/font_color`）。
2. **`Font.fallbacks` 不会进 `.tres`** —— 赋在 `FontFile` 或包一层 `FontVariation` 都一样，
   存盘再 load 回来都是 0。**只能运行时挂**（`FontFallback.gd`）。另实测：**Godot 不会自动回退系统字体**，
   项目外用字在该字体下确实渲染成方块。
3. **同一进程内 `load()` 回读会命中写入前的缓存** —— 刚 `ResourceSaver.save()` 完立刻 load，
   `default_font_size` 读到的还是上一版。回读校验改为**读文件文本**，语义校验交给独立进程。
4. **`FontVariation` 没有 `font_name`** —— 挂了兜底后字体变成 `FontVariation`，直接读 `.font_name`
   报 `Invalid access`，要取 `.base_font.font_name`。
5. **命令行 `--resolution` 会改视口** —— 截图工具改为自己设窗口尺寸，并在写图后**断言尺寸**（不符即报错），
   避免再拿缩放过的图当像素级依据。
6. **按钮高度会影响词库布局** —— 字号 20 + 内容边距 8 时，15 个词库按钮会撑出左侧面板、底部被裁；
   降到字号 18 + 上下边距 4 后装得下。
